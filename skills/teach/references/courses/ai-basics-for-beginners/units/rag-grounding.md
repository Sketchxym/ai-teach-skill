# RAG：先找相关资料，再让模型回答

<!-- node_id: rag-grounding; source_lines: 680-680; review_required: true -->

## 学习目标

理解 RAG 的检索—拼接—生成流程，并知道它能降低风险但不能保证正确。

## 核心解释

RAG 是 Retrieval-Augmented Generation，中文常译为检索增强生成。系统先从资料库找到与问题相关的片段，再把问题和片段一起放入上下文，让模型依据这些材料组织答案。这样不必把整套资料全部塞进窗口，也能使用私有或较新的文档。

## 例子

员工问报销标准时，系统先从公司制度中找“差旅报销”相关段落，再让模型基于段落回答并附出处。

## 易错点

认为接入 RAG 就不会幻觉。检索可能找错或漏掉内容，原文也可能过期，最终答案仍需核对来源。

## 可观察的掌握证据

能画出或口述“用户问题—检索—相关片段—模型回答”的链路，并说出一个失败点。
